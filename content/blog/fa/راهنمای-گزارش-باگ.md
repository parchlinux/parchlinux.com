یک گزارش باگ خوب لازم نیست طولانی باشد، اما باید اطلاعاتی بدهد که نفر دیگری بتواند مشکل را بفهمد و ترجیحاً دوباره ایجاد کند.

## عنوان دقیق بنویسید

به جای «کار نمی‌کند»، بنویسید دقیقاً کدام بخش در چه شرایطی کار نمی‌کند. عنوان اولین فیلتر برای پیدا کردن گزارش‌های مشابه است.

## مراحل بازتولید را شماره‌گذاری کنید

1. از چه صفحه یا برنامه‌ای شروع کردید.
2. چه کاری انجام دادید.
3. چه نتیجه‌ای انتظار داشتید.
4. چه نتیجه‌ای واقعاً رخ داد.

## متن خطا را کامل بفرستید

اگر لاگ یا خروجی ترمینال دارید، آن را داخل code block قرار دهید و بخش‌های مرتبط را حذف نکنید مگر اینکه شامل اطلاعات حساس باشند.

```text
command: example
expected: success
actual: error message here
```

## محیط را مشخص کنید

نسخه‌ی سیستم، سخت‌افزار مرتبط، محیط دسکتاپ و نسخه‌ی بسته‌ای که مشکل دارد می‌تواند برای تشخیص مسئله حیاتی باشد.
